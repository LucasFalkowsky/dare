# Board

## Neue Issues

Neue Issues werden in der Liste `Issues` gesammelt. Wichtig hierbei ist, dem Issue das Label **Backlog** zuzuweisen. 

## Neuer Sprint

Ein Sprint geht immer 2 Wochen. Die zugehörigen Issues für den Sprint werden im Issue Board von dem Reiter `Backlog` in den Reiter `Open` per Drag-and-Drop bewegt.

## Verantwortung für Issues

Wer ein Issue bearbeitet, hinterlegt den eigenen Account im Issue unter `Assign`. Hierfür kann man über das Issue Board auf das zutreffende Issue doppelklicken und unter `Assign` den Account hinterlegen.

## Bearbeiten eines Issues

Hierfür wird das Issue von `Open` nach `in Progress` bewegt. So lange dieses bearbeitet wird, bleibt es in diesem Reiter.

## Review eines Issues

Sollte die Bearbeitung abgeschlossen sein, wird bspw. ein `Merge Request` erstellt und das Issue nach `Review` bewegt.
Der `Merge Request` wird einer anderen Person zugeordnet, die alle Änderungen kontrolliert und ggf. Rücksprache mit der bearbeitenden Person hält.

## Abschluss eines Issues

Nach Abschluss des Review-Prozesses wird das Issue auf `done` bewegt. 

## Abschluss des Sprints

Der Scrum Master kontrolliert das Board und wählt alle Issues einzeln aus und klickt auf `close`. Somit verschwinden die Issues vom Board und ein neuer Sprint kann beginnen.
